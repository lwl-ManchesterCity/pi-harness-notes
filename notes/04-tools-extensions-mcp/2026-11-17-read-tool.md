# 2026-11-17：read Tool 的两层返回

`createReadToolDefinition()` 与其中的 `execute()` 分别返回不同的东西。

```ts
function createReadToolDefinition(cwd, options) {
	return {
		name: "read",
		parameters: readSchema,
		async execute(...) {
			return new Promise((resolve, reject) => {
				// 实际读取文件，成功或失败时交付结果
			});
		},
	};
}
```

上面是简化示意，不是完整源码。

```text
第一层 return：创建并返回 read Tool 定义对象
→ 对象包含名称、描述、参数规则和 execute 函数
→ 此时还没有读取文件

模型后来请求调用 read
→ Pi 调用 execute()
→ 第二层 return：返回代表本次读取结果的 Promise
→ 读取成功时交付文件内容，失败时交付错误
```

`execute` 函数被放进 Tool 定义时只是定义了读取流程；只有 Pi 调用它时才进入函数体。

## 读取过程中的取消

开始读取前，Pi 先检查 `signal?.aborted`；如果已经取消，直接让 Promise 以取消错误结束。

如果开始时尚未取消，Pi 会登记 `onAbort`，监听读取期间发生的取消：

```text
开始读取，aborted = false
→ 用户取消，signal 发出 abort 事件
→ 调用 onAbort()
→ aborted = true，并通过 reject 返回取消错误
```

`onAbort` 是先定义、再登记的函数；没有发生取消时不会调用。`{ once: true }` 表示该监听器最多触发一次。

## async 与 await：按顺序等待

`read` 中定义并立即调用一个异步函数：

```ts
(async () => {
	const absolutePath = await resolveReadPathAsync(path, ctx?.cwd || cwd);
	await ops.access(absolutePath);
})();
```

`async () => { ... }` 定义异步函数，末尾的 `()` 立即调用它。第一处 `await` 等路径解析完成，拿到完整路径；第二处再等待文件可读性检查。因此当前函数里的步骤按“解析路径 → 检查文件”顺序进行。

如果异步调用前不加 `await`，拿到的是代表未来结果的 Promise，而不是已经解析出的路径。等待期间不会阻塞整个程序，其他工作仍可继续。
