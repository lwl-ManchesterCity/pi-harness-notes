# 2026-11-27：切点调整

初选切点后还有两种不同的调整。特定溢出恢复场景中，若尾部满足被省略的 assistant 尝试等条件，切点可向后移动，使过长输入参与摘要；具体条件已浅看，待复习。

另一个通用调整从切点向前检查：将紧邻切点、当前不产生上下文消息的记录纳入保留范围；遇到 compaction 或产生消息的记录时停止。例如 A（消息）→ T（标签）→ B（消息，初选切点）→ C：切点向前移到 T，保留 T、B、C；再看 A 时停止。这个调整用于保留相邻的非消息记录，不是因为它们占用多少 token。

## 切点结果与对话轮次

假设同一轮对话中，位置 0 是用户提问，位置 1 是 assistant 调用工具，位置 2 是工具结果，位置 3 是 assistant 回答；保留切点选在位置 1：

```text
firstKeptEntryIndex = 1 → 从位置 1 开始保留
turnStartIndex = 0      → 被切开的这一轮从位置 0 开始
isSplitTurn = true      → 同一轮被分成切点前后两部分
```

切点本身是轮次开头时，不需要向前查找轮次起点，`turnStartIndex` 为 -1，`isSplitTurn` 为 false。切点不在轮次开头且找到轮次起点时才标记为拆分。后续压缩准备使用这些信息处理被切掉的轮次前半部分。

## 压缩主链总结

```text
AgentSession 手动或自动进入压缩
→ prepareCompaction() 构建当前投影，取得旧摘要并寻找保留切点
→ 根据切点准备普通历史和可能被切开的轮次前缀
→ 扩展可取消或提供压缩结果；否则 compact() 生成摘要
→ appendCompaction() 保存摘要和 firstKeptEntryId 等
→ 重新构建上下文：使用摘要、保留记录和压缩后的新记录
```

寻找切点先正序收集候选，再从新到旧累计 token、选择候选，随后按特殊恢复情况和相邻非消息记录调整。若切在一轮对话中间，普通历史在该轮起点前结束；该轮被切掉的前半部分单独准备摘要，切点及之后保留。已有 Session 历史不因压缩删除。

摘要模型调用、重试细节及恢复场景的完整条件本次未逐行深入；这里是主链概览。自动触发条件按计划后续阅读。

## 同一 Session 的分支与分支摘要

正常从 C 继续产生 D 是 A → B → C → D，不会产生分支。假设先有 A → B → C，再通过树形导航回到 A 并继续产生 D，历史就有 A → B → C 和 A → D 两条路径；旧记录不删除，之后可通过树形导航选择已有位置。它们仍在同一个 Session 中，不是独立对话文件。

选择生成分支摘要时，主链是：

```text
AgentSession.navigateTree() 发起导航并选择生成摘要
→ collectEntriesForBranchSummary() 找共同祖先，收集旧路径上离开的记录
→ generateBranchSummary() 生成摘要
→ SessionManager.branchWithSummary() 切换位置并追加 branch_summary
→ 刷新上下文
```

分支摘要用于把离开路径的进展带到导航后的上下文；compaction 主要用于缩短当前上下文。

`collectEntriesForBranchSummary()` 接收 SessionManager、旧叶子 ID 和目标 ID。它将旧分支的记录 ID 放入 Set，并获取目标分支路径；从目标向根倒查，首次发现也在旧路径的记录就是最近共同祖先。例如旧路径 A → H → D、目标路径 A → H → B → C：依次查 C、B、H，在 H 命中并停止；A 虽也共同，但不是最近的。

收集记录时，从旧叶子沿 parentId 回溯到共同祖先之前，再反转为从旧到新。例如旧路径 A → H → D → E，目标路径 A → H → B → C：共同祖先是 H，待摘要记录为 D、E；H 本身不包含在其中。

`generateBranchSummary()` 根据 D、E 等离开路径记录生成新的分支摘要，不是只获取已有摘要。记录可能包括用户消息、助手回复、工具结果和已有压缩摘要；共同祖先 ID 用于确定收集范围，不作为该函数的参数。原记录仍保留。

默认情况下，分支摘要和 compaction 摘要都由模型生成：Pi 的规则负责选择内容、组织摘要请求和保存结果；模型负责生成摘要文字。扩展也可提供自定义摘要结果。分支摘要将对话序列化为文字，与摘要指令组成 user 消息，再与摘要 system prompt 组成 context 交给模型；文件操作列表在模型返回后附到摘要中。

## 选择用户消息重新编辑

`navigateTree()` 用 `targetId` 找到目标记录 `targetEntry`。目标是用户消息或 custom_message 时，新的 leaf 设为目标的父记录，并取出目标文字供编辑器使用。这样编辑后重新发送的问题接在父记录后，不会先保留旧问题再追加新问题；旧分支仍在 Session 历史中。目标是其他记录时，leaf 设为目标本身。

例如 A（助手回复）→ B（用户问“检查整个项目”）→ C：选择 B 后回到 A，把 B 的文字放回编辑器，修改为“只检查登录模块”并发送，形成从 A 开始的新分支。目标的父记录用于确定新 leaf；此前查找共同祖先则用于确定离开路径的摘要范围，两者用途不同。
